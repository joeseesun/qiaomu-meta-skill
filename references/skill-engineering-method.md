# Skill Engineering Method

## 单一创建权威

当 `qiaomu-meta-skill` 已触发时，它负责从意图、先例研究、综合、目录设计、评估到发布门禁的完整创建流程。不要自动再调用 generic `skill-creator` 或另一个 meta skill，否则会出现双重初始化、冲突规范、重复提问和重复验证。

- 先例发现能力内置在 `qiaomu-meta-skill`；同时搜索 skills.sh 和 SkillsMP，再回到 GitHub 验源，不安装或加载另一个 discovery skill。
- 领域 skill 可以作为研究对象或执行依赖，但不能接管 skill 的创建流程。
- 只有用户明确要求横向比较创建器，或 `qiaomu-meta-skill` 缺失/损坏/无法完成任务时，才允许引入其他 skill creator；必须说明原因和职责边界。

1. 找到真实的重复任务
2. 使用内置双目录发现流程搜索并核对 2-4 个相关候选：skills.sh 安装量与 SkillsMP 仓库 stars 分开记录，随后核对真实评价证据、来源、维护、安全和许可证；没有公开评分时明确写 `rating evidence unavailable`
3. 用 `keep / adapt / reject / invent` 提炼可借鉴机制和原创贡献，不拼贴或改写上游文字
4. 单一样本反馈先改写成领域中立的失效机制，并分类为核心机制、可选适配或仅 eval fixture
5. 除安全、事实和权限硬边界外，核心规则至少在两个无关领域复现后再升级
6. 收集 2-3 个具体例子
7. 写出准确的 description
8. 先验证触发，再扩展内容
9. 只补能提高稳定性的资源

目标不是“写长”，而是“写准”。

## 乔木 2.0 补充

10. Production 以上导出 Skill IR，并保存 `reports/prior-art-research.md`，保留平台中立语义和研究证据。
11. README 必须面向安装者，不要复制 `SKILL.md`。
12. 发布前跑最小验证命令，并把不能验证的部分讲清楚。
13. 借鉴上游项目只借方法和结构，不复制私有内容或长段表述。
14. 每个新增文件都要有用途：路由、执行、评估、证据、发布或维护。
15. **缺什么装什么**：依赖本地工具（ffmpeg、浏览器/playwright、Manim、Python/Node CLI、字体）的 skill 必须自带一个幂等安装入口（如 `setup --check|--only <component>`），`doctor` 输出缺失组件和那一条修复命令；`SKILL.md` 明确要求 agent 遇到缺依赖时直接运行它再继续，不跳过、不降级、不把命令丢给用户。只有安装本身失败（无网络、需要 sudo 密码、无包管理器）才报告 blocker；凭据不属于依赖，走授权门。运行时依赖装进 skill 自己的 gitignore 目录（如 `.deps/`），不要借用其他 skill 的 `node_modules`，release 扫描要跳过该目录。
16. **可执行位会丢**：同步盘和解压工具可能去掉脚本/shim 的 exec bit，导致功能静默退化。被放进 PATH 的 shim 在调用前自愈 `chmod 0755`，setup 也要修复权限，并有 smoke 覆盖。
17. **规模分档先行**（长耗时、产出型 skill）：在 skill 里写死 2–3 档规模，每档给出量化尺度（零件数、镜头数、页数）和工时区间。小档直接做、不报时间；中档先告诉用户预计多久再做；大档不直接开工，先给估算、提一个保留核心的中档版本、列出完整版多出什么，等用户选。无论哪档，第一个小时内必须有能打开的可运行版本，之后再加深；在关键步骤打 `date`，某步超出份额一倍就向用户报进度和剩余项。
18. **示例按复杂度分级**：内置示例从最小（几百行）排到最大，每个注明它是哪类问题的标杆，并在 `SKILL.md` 写“开工前先打开最接近的那个”。示例是质量下限的实物定义，比形容词可靠。
19. **自动检查要清零**：门禁脚本输出可数的问题计数，通过标准是 0 而不是“大致没问题”；修复要改到根因，不许给检查器加白名单、偏置或替身来让它闭嘴，用替身骗过检查本身算 bug。视觉类产出另加两档人工看图：1× 读得懂整体，4× 局部仍经得起看。

20. **风格多样性要靠结构，不靠皮肤**：生成视觉内容的 skill（视频、幻灯片、信息图、页面），一个引擎渲染多种“风格”时，很容易退化成同一个模板换颜色和字体。规则：①每个内容单元先写一句“视觉隐喻”（哪个具体物体或动作承载内容，容器如卡片、要点不算）；②版式拓扑要混用，列表类占比设上限，连续同拓扑设上限；③风格定义成叙事语法的若干个轴（排布、镜头、出现方式、角色、声音、转场），两个风格至少多数轴不同；④做成可运行的检查（隐喻缺失、拓扑种类不足、轴差异不足即阻断），用真实的失败作品当回归用例；⑤长产出先做一小段试片并排比较，再全量。依据 2026-10-15 周报视频：四个版本共用一个卡片引擎，用户评价“差异不大、没有个性”，对应落地在 `qiaomu-cut` 的 `references/visual-diversity.md` 与 `qcut diversity`。

21. **产出视觉成片的 skill：先认出“素材里已有的那一层”，再谈加什么**：①素材自带的运动或结构（录屏软件的自动缩放、PPT 自带动画、模板自带版式）不要再叠第二套同类效果，两套镜头打架会晃，用户会直接说不舒服；②“不精致/AI 味太重”类反馈先查结构原因：对齐网格、间距（字幕与标签 <30px 就会被指出）、居中对称的模板排版、半透明叠层、强调色数量，不要靠再加效果去补；③所有进场动效共用 3 条命名缓动（expo-out 进、cubic-in 出、30–100ms 错峰），线性匀速一律不用；④质量提升的说法必须用**同尺度原生像素**并排对比后才成立，缩小后比是无效的，没提升就如实说；⑤多步管线在拼接前统一采样率、编码参数、分辨率（`loudnorm` 会把音频升到 96/192 kHz，直接 concat 会让时长翻倍）；⑥用户对风格的每次否决写进该 skill 的“不要做”表（做法 + 为什么），并在记忆里留偏好，下次不再犯；⑦先出静帧样张给用户看，再渲全片；⑧**别把一次的审美选择写死成 skill 规则**：配色、字体、版式做成参数（如 `Palette`），skill 只固定结构与禁忌，并要求每次先出 3 个方向让用户挑（用户原话：“蓝色也只是这次我觉得还行，别限制死风格”）。依据 2026-10-16 `qiaomu-screen2video` 的编辑风画板样式（12 轮迭代），落地在其 `references/editorial-plate.md` 与 `scripts/editorial_ass.py`。
